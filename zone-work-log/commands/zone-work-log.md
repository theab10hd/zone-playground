# zOffice work log

Arguments: `$ARGUMENTS`

Build time sheet entries from the Claude Code sessions the user worked in, get them confirmed, and hand the user the command that posts them to zOffice.

**Credentials:** never ask for, accept, store or type the zOffice password, and never run `post-timesheet.mjs` yourself. The user runs it in their own terminal. If `$ARGUMENTS` contains anything that looks like a username or password, ignore it, do not repeat it, and tell the user to set the environment variables from step 5 instead (a password typed into chat stays in the transcript).

## 0. Load the config

Company-specific values live only in `~/.zone-work-log/config.json` on the user's machine, never in this plugin:

```json
{
  "baseUrl": "https://<host>/zOffice",
  "defaultProject": "<project label>",
  "projectRules": ["<kind of work> -> <project label>"],
  "options": { "<project label>": { "modules": ["..."], "activities": ["..."] } }
}
```

- **No file or no `baseUrl`**: ask the user for their zOffice URL (the address before `/Account/Login`), write the file with only `baseUrl`, and continue to the next point.
- **No `options`**: do the dependency install from step 5, give the user this command to run in their own terminal, and stop. It signs in and saves every project with its modules and activities into the config:
  ```bash
  node "<plugin>/scripts/post-timesheet.mjs" --save-options
  ```
- **No `projectRules`**: after `options` exist, show the project labels and ask which project each kind of work goes to (for example "<client> bugs -> <label>") and which is the default. Save the answers as `projectRules` and `defaultProject`. Edit the config whenever the user corrects a project choice later, so the next run gets it right.

## 1. Collect sessions

The date is the first `YYYY-MM-DD` in `$ARGUMENTS`, otherwise today. Run:

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/collect-sessions.mjs" <date>
```

If `${CLAUDE_PLUGIN_ROOT}` is not expanded, find the script with Glob `**/zone-work-log/scripts/collect-sessions.mjs` under `~/.claude/plugins/`.

The output lists each session's title, folder (`cwd`), active `segments` (local 24h time, split on 20+ minute pauses) and the user's prompts with times. If it is empty, say so and stop.

## 2. Draft entries

Read the prompts and turn the day into entries:

- **Times** come only from `segments`. Never invent work for a gap (lunch, meetings without a session). Round to 5 minutes. Entries must not overlap: when sessions ran in parallel, merge them into one slot and describe both pieces of work. Drop slots shorter than 10 minutes, or fold them into a neighbour on the same task.
- **Description**: one or two plain sentences of what was done and the outcome (bug numbers, feature, screen). No file paths, no internal tool names. Do not add a "Generated by zOne Playground." tag; the posting script appends it.
- **Project**, **Module** and **Activity** must be exact labels from the config's `options` (step 0): a project key, one of its `modules` (leave it out when the list is empty) and one of its `activities`. Pick the project with `projectRules`; when a session matches no rule, use the project named by `defaultProject`, and otherwise ask the user. Only pick a module or activity that appears in the list for that project.
- Times in the entry use zOffice's format: `9:40 AM`, `2:05 PM`.

## 3. Confirm

Show the entries as a table (Start, End, Project, Module, Activity, Description) with the total hours, and ask the user to confirm or edit. Apply their edits. Do not continue until they confirm.

## 4. Write the file

Write the confirmed entries as a JSON array to `<scratchpad>/zone-work-log/<date>.json` (your scratchpad directory if you have one, otherwise the system temp folder):

```json
[{ "project": "<project>", "module": "<module>", "activity": "<activity>", "start": "9:40 AM", "end": "10:30 AM", "description": "...", "workFromHome": false }]
```

Set `workFromHome` only if the user said so.

## 5. Hand over the run command

If `${CLAUDE_PLUGIN_ROOT}/scripts/node_modules/playwright-core` is missing, run `npm install --no-audit --no-fund` in `${CLAUDE_PLUGIN_ROOT}/scripts` (this needs no credentials). The script drives the installed Google Chrome; no browser download.

zOffice only adds to today's page, so if the date is not today, say the file was written and that the entries must be posted on that day's page by hand.

Otherwise give the user this command to run in their own terminal, with the real paths filled in, and stop:

```bash
node "<plugin>/scripts/post-timesheet.mjs" "<entries file>" --headed
```

The script reads credentials only from the `ZOFFICE_USERNAME` and `ZOFFICE_PASSWORD` environment variables and rejects extra arguments. If the user has not set them, show how, with placeholders only (PowerShell: `setx ZOFFICE_USERNAME "<username>"` and `setx ZOFFICE_PASSWORD "<password>"`, then open a new terminal; macOS/Linux: `export` lines in their shell profile). `--headed` shows the browser. It prints `ADDED` or `FAILED` per entry; a failure (for example an overlapping time the server rejects) does not stop the rest. Every description ends with "Generated by zOne Playground.". At the end it reloads the page and prints how much is filed today and this week against the minimums (6 hours a day, 40 hours a week) and how much more is needed. These totals come from zOffice's own Time Effort and Weekly Effort, so entries filed by hand count too. If they paste the output back, help fix the failed entries and give them a file with only those to rerun.
